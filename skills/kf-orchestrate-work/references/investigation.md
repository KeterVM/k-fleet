# Investigation route

Use this route to explain unclear behavior.

1. State the question, observed versus expected behavior, scope, and evidence that
   would distinguish plausible causes.
2. Inspect execution paths, configuration, logs, tests, or history relevant to the
   symptom. Prefer focused reproductions over broad speculation.
3. Separate confirmed facts, supported hypotheses, counterevidence, and unknowns.
4. Report the most likely cause with confidence and the next discriminating action.

Keep diagnosis-only requests read-only. When the user has requested investigation
and correction, existing authority covers relevant reversible local instrumentation,
the fix, and validation; remove temporary instrumentation before completion.
Continue to bug fix for a demonstrated contract violation or implementation for an
authorized behavior change without requesting permission merely to change routes.
Use verification when an independent verdict is required.
