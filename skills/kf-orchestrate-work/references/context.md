# Context route

Use this route to initialize, audit, or change repository instructions and the
source documents that govern future agent behavior.

1. Resolve the exact repository, subtree, files, and representative working
   directories in scope. Inspect ancestors needed to compute effective instructions
   without treating them as writable.
2. Discover current instruction files in runtime precedence order, including
   supported overrides and fallback names. Account for empty shadowing files,
   nested scope, routed documents, and configured byte limits.
3. Verify commands, paths, architecture facts, ownership, and links against current
   repository evidence. Separate an explicit policy decision from a fact, inferred
   convention, preference, or unapproved memory.
4. For an authorized change, edit the narrowest source that produces the intended
   effective behavior. Prefer concise pointers and deletion of duplication over
   copying detailed procedures into always-loaded instructions.
5. Recompute the effective chain for representative directories after the edit and
   verify scope, precedence, size, links, and source-over-memory behavior.

Do not invent policy or write outside the user's scope. Store the resulting source
revision and a compact change episode in memory, but keep the repository file as
the authority.
